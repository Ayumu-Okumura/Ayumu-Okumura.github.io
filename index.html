Project

Debt Calculator

This is the one of the programming project developed outside school work. The main reason of implementing this project is to learn Python coding and apply the knowledge of coding from C++, C#, and Java programming class.

This program is to calculate the debt and show how much is the interest and remaining amount based on user input. This program asks users to put debt amount, interest rate, interest interval, and type of interest. This project currently supports only yearly interval with simple interest. However, this program is designed to support all yearly, monthly, weekly, and daily interest with both simple and compound interest. It will be updated on Github.

Once user enters the all the debt information, the program asks user to enter paid amount for each interval. In this example, $20 is entered for each year interval to see interest amount change.

When the user decides to quit or the amound reaches zero, This program shows summary of the payments. It starts with showing the information the user entered: debt amount, rate, type of interest, and interval of interest. It shows how much paid, the remaining of the principle, interest amount of each interval, total amount of interest, and lastly total amount of debt.

Lastly the program generates bar graph to visualize the changes of the remaining amount and interst amount, and it will also show the extra amount from the last payment if there is any.

Because this project is still in development, there is some features that is not finished, such as, save and load function to let users continue where they stopped and estimate function to calculate how long to take based on the users' input.

Mock Game Library

This project is about creating Entity Relationship Diagram and Microsoft Access database and generate reports based on the data. The purpose of this project was to demonstrate the skill of designing detabase using data from Steam database.

The first picture shows all the relationship used in this project. Category table has zero or more game. Game table has one or more category. Game_Category table is a bridge table connecting game and category tables preventing many-to-many relationship. Game has one difficulty, and difficulty has zero or more games. Game has zero or more players, and player has zero or more games. Player_Game_Info table connect both table and store played hour, purchased date, and last played date.

The second picture is an example of data in GAME table. It contains game ID, game name, developer name, price of game, date published, download containts availability, and 3 level of difficulty.

The last part of projecft is to generate reports. The last picture shows one of reports generated based on query. This report is to list games which was less than $20 and bought after 2023.

This project was valueable for him to build database based on real-world data.
