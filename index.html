Project

Debt Calculator

This is one of the programming projects developed outside of schoolwork. The main reason for implementing this project is to learn Python coding and apply it the knowledge of coding from C++, C#, and Java programming class.

This program is to calculate the debt and show how much is interest and the remaining amount based on user input. This program asks users to put the debt amount, interest rate, interest interval, and type of interest. This project currently supports only a yearly interval with simple interest. However, this program is designed to support all yearly, monthly, weekly, and daily interest with both simple and compound interest. It will be updated on GitHub.

Once the user enters all the debt information, the program asks the user to enter the paid amount for each interval. In this example, $20 is entered for each year interval to see the interest amount change.

When the user decides to quit or the amount reaches zero, this program shows a summary of the payments. It starts with showing the information the user entered: debt amount, rate, type of interest, and interval of interest. It shows how much is paid, the remaining principal, the interest amount of each interval, the total amount of interest, and lastly, the total amount of debt.

Lastly, the program generates a bar graph to visualize the changes of the remaining amount and interest amount, and it will also show the extra amount from the last payment if there is any.

Because this project is still in development, there is some features that is not finished, such as, save and load function to let users continue where they stopped and an estimate function to calculate how long to take based on the users' input.

Mock Game Library

This project is about creating an Entity Relationship Diagram and a Microsoft Access database and generating reports based on the data. The purpose of this project was to demonstrate the skill of designing a database using data from the Steam database.

The first picture shows all the relationships used in this project. The category table has zero or more games. The game table has one or more categories. The Game_Category table is a bridge table connecting the game and category tables preventing many-to-many relationship. A game has one difficulty, and difficulty has zero or more games. A game has zero or more players, and a player has zero or more games. The Player_Game_Info table connects both tables and stores the played hour, purchased date, and last played date.

The second picture is an example of data in the GAME table. It contains game ID, game name, developer name, price of game, date published, download contents availability, and 3 levels of difficulty.

The last part of the project is to generate reports. The last picture shows one of the reports generated based on the query. This report is to list games which were less than $20 and bought after 2023.
